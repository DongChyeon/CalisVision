# ADR-0008: AC-4 게이트 재정의 — "기준 홀드에서 정렬 결함 오탐 없음 + 평균 θ ∈ [175,185]"

## Status
Accepted

## Date
2026-09-27

## Context
AC-4(NFR-5)의 원래 게이트: hold-out 영상의 홀드 구간(≥ 50 샘플)에서 스무딩(이동 중앙값 5) 전신 정렬 θ의 **≥ 95%가 [175°,185°]**, 스무딩 null은 실패로 계수. 구현은 `AlignmentGate`.

**이 재정의는 hold-out 결과를 본 뒤에 내린 사후(post-hoc) 결정이다.** hold-out 세 번의 결과(`docs/VERIFICATION.md` P4, 모두 파라미터 동결·1회 평가):

- **holdout**(17.7 s): strict **FAIL** — 홀드 130..176 = 47 샘플 < 50, θ∈[175,185] 19.1%. 육안 확인 결과 양손·손목이 쿠션 뒤에 가려져 있었다(팔꿈치 267° 같은 불가능한 값). 입력이 촬영 가이드를 만족하지 못한 것으로 기록하고 재촬영.
- **holdout2**: 발목이 프레임 밖이라 **평가 전 기각**(각도 미계산).
- **holdout3**(13.9 s, 손·발 가림 없음): strict **FAIL** — 홀드 24..139 = 116 샘플 ✓, θ∈[175,185] **61.2%** < 95%. 평균 184.9°, 범위 181.9–189.2°로 전 구간 바나나 쪽. 실패 샘플 45개는 모두 185–189° 쪽이며 홀드 진입 직후(~1.5 s)와 끝부분(~2 s)에 몰려 있고, 가운데 ~7 s는 대부분 게이트 안이다. 샘플 62·101에서 LEFT 손목·팔꿈치·어깨·엉덩이·무릎·발목 6개 landmark가 모두 몸 위에 놓이는 것을 육안 확인(측정 오류가 아님).

튜닝 영상(손 보임)도 같은 strict 게이트에서 43.6%로 실패했다 — 실제 자세가 홀드 중 ±9° 움직였다.

## Decision
AC-4를 다음으로 재정의한다(2026-09-27 사용자 결정). 곧은 기준 홀드(홀드 ≥ 50 샘플)에서 두 조건을 모두 충족하면 PASS:

1. **정렬 결함 오탐 없음** — 동결된 `HandstandKnowledge` 전신 정렬 규칙(`Deviation(10,10)`, 바나나 등/파이크)으로 `FaultEvaluator`(연속 ≥ 3 샘플)를 돌린 결과, 홀드와 ≥ 3 샘플 겹쳐 홀드로 clip된 결함(결과 화면 목록과 같은 규칙)이 **0건**.
2. **평균 정렬 θ ∈ [175°,185°]** — 홀드 구간 스무딩 θ의 평균.

홀드 샘플의 null(측정 불가)이 **5% 초과면 FAIL**. 구현은 순수 함수 `domain/analysis/ReferenceHoldGate.evaluate(timeline, hold, rule)`. 임계값·스무딩·`HoldSegmentDetector`·규칙은 변경하지 않는다. 기존 `AlignmentGate`(strict [175,185]/95%)는 남겨 **정보용 지표**로 계속 보고한다.

결과(holdout3, `WallHandstandAlignmentTest`): 홀드 24..139(116), null 0, 평균 184.9°, 최대 189.2° → 홀드 안 정렬 결함 0건 → **PASS**. strict 지표 61.2%는 함께 기록한다.

## Drivers
- 앱이 사용자에게 보여 주는 것은 결함 목록이고, 전신 정렬 결함 임계값은 ±10°다. AC-4가 검증해야 할 성질은 "곧은 홀드를 잘못 결함으로 지적하지 않는다"이다.
- strict 게이트(±5°를 95% 유지)는 **측정 정확도와 사람이 ±5° 안에 머무는 능력을 섞어서** 본다. 가림 없는 holdout3도, 튜닝 영상도 실제 자세 흔들림만으로 실패했다.
- 파라미터 동결 원칙 유지 — 게이트만 바꾸고 판정 로직·임계값은 그대로 둔다.
- 측정 불가(null)가 많은 영상이 결함 0건으로 통과하는 구멍을 막아야 한다(null 5% 상한).

## Alternatives
- **strict 게이트 유지, AC-4 FAIL 확정** — 정직하지만 통과 가능한 영상이 사실상 없고(세 영상 모두 미달), 실패 원인이 인식 품질이 아니라 사람의 자세 흔들림이라 제품 품질 신호로서 의미가 약하다. 기각.
- **폭 완화([170,190] 등) 또는 비율 완화(80% 등)** — 수치를 결과에 맞춰 고르는 것이 되고, 앱의 실제 결함 임계값과도 연결되지 않는다. 기각.
- **또 한 번 재촬영** — holdout3은 가림 없이 landmark가 몸 위에 있음을 확인했으므로 재촬영으로 해결될 문제가 아니다(자세 흔들림은 사람 특성). 기각.
- **임계값·스무딩 재보정** — hold-out을 이미 열람했으므로 재보정에는 새 hold-out이 필요하고, 동결 원칙을 깬다. 기각.

## Why chosen
재정의된 게이트는 앱이 실제로 내는 판정(±10° 결함, ≥ 3 샘플, 홀드 clip)에 직접 묶여 있어 "곧은 기준 홀드에서 오탐이 없다"는 사용자 관점의 정확성을 검증한다. 평균 θ 조건으로 전체적인 치우침(±5°)도 여전히 본다. strict 지표를 버리지 않고 보고해 정보 손실이 없다.

## Consequences
- AC-4 **PASS**(ADR-0008 기준). strict 지표(61.2%)와 원래 기준으로는 FAIL이었다는 기록은 `docs/VERIFICATION.md`에 그대로 남긴다.
- **원래 게이트보다 약하다**: ±10° 안에서의 흔들림(예: 186–189°가 계속 이어지는 홀드)은 통과한다. 평균 조건만으로는 홀드 일부의 ±5° 이탈을 잡지 못한다.
- 사후 재정의라 확증 편향 위험이 있다 — 결과를 본 뒤 기준을 골랐다는 사실을 명시적으로 남긴다.
- 근거는 **단일 기기**(SM-F766N)·**단일 영상**(holdout3)·**낮은 카메라 각도**(바닥 근처에서 올려다봄, 가이드의 엉덩이 높이 아님)이며 발이 화면 위 가장자리에 닿아 있다.
- 스펙(`.omc/specs`)과 NFR-5의 AC-4 문구는 본 ADR로 **대체(superseded)** 된다. `docs/REQUIREMENTS.md` AC-4 행과 VERIFICATION AC 대조표를 갱신한다.
- hold-out fixture(`app/src/test/resources/fixtures/wall_handstand_holdout.json`, holdout3)를 커밋해 `WallHandstandAlignmentTest`가 skip 없이 실행된다.

## Follow-ups
- 가이드 구도(엉덩이 높이 카메라, 몸과 수직) hold-out을 확보하면 같은 게이트와 strict 지표를 재측정한다.
- 다른 기기·다른 사람의 기준 홀드로 오탐 없음을 재확인한다.
- 물리적으로 불가능한 각도·프레임 간 급변을 "측정 불가"로 처리하는 방어 규칙 검토(P4 진단 후속) — 도입 시 null 비율 조건과의 상호작용을 확인한다.
